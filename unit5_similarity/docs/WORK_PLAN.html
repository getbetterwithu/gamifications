🛠️ 5단원 게임 — 최종 작업 계획

기획서 confirm 이후, 버그 없이 가장 자연스러운 작업 순서

🧭 이 순서를 짠 5가지 원칙

  • 의존성 역순 금지 — 남이 참조하는 것(문제·캐릭터)을 먼저 만든다. scenario.js는 맨 나중.
  • 데이터 먼저, 통합 나중 — problems.js(데이터) → scenario.js(흐름) → 엔진 통합 순. 데이터가 흔들리면 위가 다 무너짐.
  • 검증 가능한 단위로 끊기 — 각 단계 끝에 "눈으로 볼 산출물"(스토리보드 HTML 등)을 둬서 버그를 일찍 잡음.
  • 독립 작업은 유연 배치 — 사운드·배경처럼 의존 없는 건 별도 트랙. 메인 흐름을 막지 않음.
  • 위험한 신규 기능은 작게 먼저 검증 — 황금비 인터랙션·사운드는 프로토타입으로 리스크부터 제거.
0

확정 (기획서 confirm)

선행 필수
  • 기획서 confirm + 미결정 4가지 확정: 문제 개수 / 엔딩 분기 / 문제 배정 / 캐릭터 이미지
⚠️ 여기가 안 정해지면 뒤가 전부 흔들립니다. 특히 문제 개수·배정이 Phase 1의 입력값.
1

문제 데이터 확정 (problems.js)

기반 데이터
  • 15문제 중 스토리에 쓸 것 / 뺄 것 분류
  • 각 문제를 스토리 자재(벽돌·유리·점토 등)에 맞게 수치·맥락 각색
  • 황금비·A4(반닮음) 신규 문제 2개 별도 작성
  • 문제 정답 전수 검수 (교과서 크롭과 대조 — 그림 라벨 의존 문제 주의)
  • problems.js 작성 (slot ID 확정 — 이게 scenario가 참조할 키)
선행: Phase 0
검증: 단일 문제 테스트 페이지로 각 문제가 정답 판정·힌트까지 정상 작동하는지 확인.
왜 먼저? scenario.js가 문제 ID를 참조하므로, ID·정답이 먼저 굳어야 함. 정답 검수를 여기서 끝내야 나중에 안 흔들림.
2

문제 도형 제작 (SVG)

자산
  • 도형 필요한 문제의 SVG 작도 (교과서 PNG 그대로 안 씀 — 저작권 + UI 통일)
  • 게임 톤에 맞춘 색·선 스타일 적용
선행: Phase 1 (어떤 문제를 쓸지 확정돼야 함)
검증: 도형이 문제 의도(수치·각도)와 일치하는지 대조.
Phase 1과 살짝 겹쳐 진행 가능(문제 확정된 것부터 도형 착수). 단 "뺄 문제"의 도형을 그리는 헛수고를 막으려면 Phase 1 분류 후 시작.
3

스토리보드 작성 (scenario.js)

흐름
  • Scene 단위로 전체 흐름 작성 (도입→자재 퀘스트→탈레스 최종→결말)
  • 확정된 문제 slot ID를 각 Scene에 배치
  • 대사·클릭 줄이기 원칙 적용 (2~3문장 묶기, step 30~40% 감축)
  • 신규 캐릭터(테론·소폴로스) 대사·등장 연출
  • 엔딩 분기 작성 (Phase 0에서 정한 방식대로)
선행: Phase 1 (문제 ID), 캐릭터(완료 ✅)
검증: storyboard.html로 전체 스토리를 띄워 흐름·대사량 확인 (4단원처럼).
문제 ID가 굳은 뒤 작성해야 "없는 문제 참조" 버그가 안 남. 도형(Phase 2)은 scenario와 독립이라 병행 가능.
4

황금비·A4 인터랙션 구현

신규 기능
  • 먼저 프로토타입: 슬라이더로 직사각형 비율 조절 + "닮은꼴 되는 순간" 감지 (단독 HTML로 리스크 제거)
  • 비례식 빈칸 채우기 연동
  • 검증 후 게임 엔진(탈레스 최종 관문 / A4 초반)에 통합
선행: Phase 1 (황금비·A4 문제 정의)
검증: 프로토타입 단독 작동 → 그 다음 엔진 통합. 통째로 넣다 터지는 것 방지.
기존 6유형(ox·choice…)에 없는 새 인터랙션 타입이라 가장 버그 위험 큼. 그래서 작게 먼저 검증하고 통합.
5

엔진 통합 & 플레이 테스트

통합
  • index.html 엔진에 problems / scenario / 도형 / 인터랙션 전부 연결
  • 4단원 엔진 재활용 부분 점검 (평가 시스템·PDF·세이브)
  • 처음부터 끝까지 1회 완주 플레이 테스트 (모든 문제·분기·엔딩)
  • 버그 수정
선행: Phase 1~4 전부
검증: 풀 플레이 1회. 각 퀘스트 클리어→자재 획득→신전 단계 진행→엔딩까지.
6

배포 & 허브 등록

마무리
  • hub.html(게임 진입 안내) 작성 (4단원 형식)
  • GitHub Pages 배포 + ai-labs games.json에 5단원 카드 추가
선행: Phase 5

🔀 별도 트랙 (언제 해도 됨 — 메인 흐름과 독립)

🔊 사운드 (BGM·SFX) — 다른 작업에 의존하지 않음. 권장: Phase 5(통합) 즈음에 넣는 게 가장 효율적.

  • 이유: 너무 일찍(Phase 1~3) 넣으면 Scene·이벤트가 바뀔 때마다 사운드 연결을 다시 만져야 함 → 헛수고·버그
  • 이유: 너무 늦게(배포 후) 넣으면 통합 테스트를 또 돌려야 함
  • → Scene 구조가 굳은 Phase 5에서 "이벤트별 효과음 + 장면별 BGM"을 한 번에 매핑하는 게 최적
  • 4단원 엔진에 playBgm() 흔적 있음 → 재활용 가능한지 그때 점검

🎨 배경 이미지 — 5단원에 이미 9장 있음(harbor·library·basement 등). 스토리 확정 후 부족한 장면만 추가 생성. Phase 3~5 사이 유연하게.

📊 전체 흐름 한눈에

0. confirm 1. 문제 데이터 2. 도형 SVG 3. 스토리보드 4. 황금비 인터랙션 5. 통합·테스트 6. 배포

※ Phase 2(도형)·4(인터랙션)는 Phase 1 확정분부터 병행 착수 가능. 사운드·배경은 별도 트랙으로 Phase 5 즈음 합류.
※ 핵심 직렬 경로(반드시 순서대로): 0 → 1 → 3 → 5 → 6. 나머지는 이 뼈대에 붙는 가지.
